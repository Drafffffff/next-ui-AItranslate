# Brick Mic：语音输入与 Codex 控制设计

当前掌机页面与操作以 [掌机交互](BRICK-MIC-INTERACTION.md) 为准；下文保留早期方案与原型记录。

日期：2026-10-02。状态：交互原型已确认，在 `codex/brick-mic-control` 实现；Mac正式版0.4.11已由用户实测确认任务选择、口述填入和掌机X回车发送通过。基础输入、控制协议和提醒已编译验证；新建桌面任务的自动元数据发现仍待后续接入。

交互原型：[在 Mac 浏览器打开](../ports/brick-mic/prototype/index.html)。原型只模拟输入、任务与通知，不连接掌机、不调用识别服务、不修改真实应用或系统设置。

## 1. 产品目标与确定的约束

打开 Brick Mic 后即可按住 A 说话。没有启动欢迎页、模式选择页或每次录音前的任务选择。

- 普通模式沿用当前语音输入：用户在 Mac 上选择输入框，Brick 不主动切换 Mac 窗口。
- Codex 模式绑定明确的任务 ID。用户从 Brick 选任务后，Mac 自动打开该任务、聚焦输入框；Mac 正在其他应用时也能主动定位回来。
- 两种模式的十字键、肩键和 B 都编辑 Mac 输入框，**Brick 不维护可编辑草稿**。掌机的识别结果是本次口述的回显，不冒充 Mac 输入框全文或光标位置。
- 识别结果只填入；**只有在 Brick 按 X 才提交 Codex 消息**。恢复、重连、切换模式都不自动发送。
- START 一键切换模式；Y 只负责选择任务；SELECT 只负责编辑菜单；MENU 保持退出应用。
- 电量、充电状态和连接状态常驻顶部；系统主题和字体仍来自 NextUI。
- **A 唤醒仅在 Brick Mic 内生效**；息屏按住 A 直接录音，同次松开结束，不绑定全局按键。
- 短按电源只息屏待机，保留蓝牙与后台服务；长按关机才停止。继续保留应用开机恢复。

## 2. 模式与进入流程

### 普通输入

主界面显示「普通输入」和已知的前台应用名称。用户自行点击 Mac 输入框；按住 A 录音时锁定本次输入目标。最终结果只输入到仍然有效的目标。

自动输入关闭时保持原有开关行为：结果仅回显，可由用户复制。目标应用、输入焦点已变化或权限不足时保留识别结果并提示原因，不猜测其他输入目标。

### Codex 控制

首次按 START 进入 Codex 时打开任务列表；选中任务后回录音主界面。以后恢复上次任务，失效时才要求重选。任务名称是显示标签，绑定依据是 threadId。

每次选任务、开始口述、执行编辑或发送操作，都经过同一个定位入口：

1. 检查 Codex 及控制适配器是否可用。
2. 按任务 ID 打开目标会话，并激活其窗口；已处于对应任务时复用当前页面。
3. 以主页面顶部任务标题核对规范元数据；优先复用已经聚焦的消息输入框，否则按输入框的真实可访问性标签查找并聚焦。
4. 确认当前窗口、文本焦点与本次操作仍有效，返回定位结果；不反复遍历全部历史或依赖侧栏选中状态。
5. 定位成功后执行操作；失败显示「无法定位输入框」，不向其他元素发送按键。

录音可在定位等待期间开始上传；定位未完成时保留本次结果在 Mac 内存中，不能自动提交。任务选择尚未成功时不切换已绑定任务。

口述结束只填入文字。用户按掌机 X 后，在已定位的消息输入框发送 Return；不额外寻找 Send 按钮，也不在识别结束后自动回车。SE 菜单的换行继续使用 Shift+Return，与发送分开。

首次查找、重连或任务加载需要 Loading；已有目标的连续编辑复用短期定位结果，并由焦点/窗口变化事件使缓存失效。不能只凭前台进程是 Codex 就认为任务正确。

### 返回普通输入

在 Codex 主界面按 START 即返回普通输入，清除活动任务控制绑定，保留「上次任务」供下次恢复。Mac 中已经填入但未发送的文字留在原任务输入框。

返回普通输入不自动恢复或猜测其他窗口，不继续激活 Codex。用户自行选择 Mac 输入位置。X 不再执行 Codex 提交。任务提醒订阅保留，但通知不能抢焦点或强制切回 Codex。

正在录音、识别或执行发送时不切模式，短提示「本次输入完成后可切换」。B 可取消录音/识别，随后再切换；取消时迟到的结果按会话编号丢弃。发送已经提交后 B 不作为撤回。

### Codex 可用性变化

Mac 在连接建立时发送能力快照，随后监听应用启动、退出及适配器变化。按 bundle ID 和实际功能识别，不按应用文件名判断；当前本机安装名为 ChatGPT，不能因名称变化误判。

- 普通模式中 Codex 不可用：隐藏任务、任务发送和进入 Codex 的提示；普通输入与编辑不受影响。
- Codex 打开：出现 START 进入入口，不自动切换模式。
- 正在 Codex 模式时退出/桥接失效：停止控制，显示「Codex 已关闭」或「任务连接中断」；保留本次结果和原输入框内容。START 始终可回普通；不能静默把识别结果改投当前应用。
- 全新启动且 Codex 不可用：直接普通输入；模式偏好可保留，下一次可用时由用户主动进入。

## 3. 按键规范

| 按键 | 输入主界面 | 任务列表/菜单 |
|---|---|---|
| A 按住/松开 | 开始/结束口述 | 短按确认选项，不录音 |
| 十字键左右 | Mac 光标左右移动 | 左右用于页切换，只有确实需要分页时显示 |
| 十字键上下 | Mac 光标按显示行移动，语义由编辑器决定 | 移动选择项 |
| L 或 R + 十字键 | 相当于 Shift + 方向键，扩大/缩小选区 | 不执行远程选字 |
| B | 删除选区或光标前一个字符；录音/识别中取消本次输入 | 返回输入主界面，不删除文字 |
| X | 仅 Codex 模式：定位并提交当前输入框内容 | 禁用，避免列表中误提交 |
| Y | 仅 Codex 模式：打开任务列表 | 返回任务列表/切回输入页 |
| START | 切换模式 | 回普通模式；普通模式下未完成选任务时取消进入 |
| SELECT | 打开编辑菜单 | 关闭编辑菜单 |
| MENU | 退出 Brick Mic，清理按键状态；保留 Mac 中未发送内容 | 同左 |
| 电源短按/长按 | 息屏待机/关机 | 同左 |

编辑菜单第一版提供：撤销、重做、复制、粘贴、全选、插入换行、阅读本次识别。复制与粘贴操作 Mac 的剪贴板；换行按目标编辑器适配，必须验证不会提交消息。暂不增加容易误用的清空全文快捷键。

中文/emoji 的删除与移动由 Mac 编辑器处理，不用 BLE 字节偏移模拟字符。支持撤销，语音填入替换 Mac 当前选区。未证明辅助功能全文与选区读取可用前，不在 Brick 绘制虚假的同步光标。

长按采用单调时间而非帧计数：十字键立即一步，350ms 后以 90ms 间隔重复，按住 1.2s 后约 45ms；B 用 400ms 延迟和 100ms 间隔，删除不继续加速。数值为交互起点，需实机调整。

每条编辑命令携带当前是否选字的标志，Mac 合成完整按下/松开，不通过蓝牙维持系统 Shift 长按状态。松键、断连、切页、待机和关机均终止重复；迟到按键拒绝执行。

输入框为空时，部分编辑器会把 ↑ 用作恢复旧提示；Codex 适配器应在能确认输入为空时阻止这种意外行为。读取失败时不能声称具备精确空输入保护。

## 4. Brick 页面与信息层级

显示基准为 1024 × 768，布局与当前 PocketJS 主界面一致。主要正文 40px，标题约 54px，状态及按键标签至少 30px；优先减少文案，不能靠缩字号塞入任务信息。

主界面自上而下：

1. 顶栏：应用名、蓝牙连接状态、电池图标＋百分比；充电时增加充电标记。
2. 目标行：「普通输入 · 备忘录」或「Codex · 任务名称」。任务名过长省略，完整名称在任务列表可查看。
3. 主状态：「按住 A 说话」「正在录音」「正在识别」「正在打开任务」「已填入，按 X 发送」。
4. 内容区：录音波形或本次最终识别文字。任务处理时显示简单状态，不流式刷新全部任务日志。识别文字较长时通过编辑菜单的阅读页查看，阅读页十字键只滚动，不遥控 Mac。
5. 底栏：仅当前可用的关键操作，模式切换的目标写清楚，如「START 普通输入」。次要快捷键放 SELECT 菜单/帮助页，避免一次塞下全部按键。

任务列表每页约 4–5 项，标题、运行/待回复状态、未读标记。选中项沿用 NextUI 选中配色。只取标题、状态和必要摘要；本轮回复全文按需查看，首版不做完整历史浏览或任务删除。

任务页入口、识别回显、通知条和 Mac 输入框各自职责明确：识别回显不是可编辑草稿，通知不是自动发送命令。

## 5. 电量与充电显示

2026-10-01 通过只读 SSH 确认本机具有：

- `/sys/class/power_supply/axp2202-battery/capacity`，该次读取为 95。
- `/sys/class/power_supply/axp2202-battery/status`，该次读取为 `Discharging`。
- `/sys/class/power_supply/axp2202-usb/`，可进一步核对 USB 在线状态。

Brick 自行读取电源接口，不依赖 Mac 或蓝牙。启动/唤醒立即采样，亮屏每 15s、息屏每 60s 采样；百分比/充电状态变化时向 Mac 推送，重连发快照。读取错误显示「—%」，不当作 0%，不保留过期值假装实时。

状态包括放电、充电、已充满、未知。充电时不能仅以 USB 插入代替实际充电状态。图标和文字共同表达低电量，颜色遵循主题并保留可读性；20% 以下显示低电量，10% 以下一次提醒，5% 以下再次提醒，使用回升阈值防止反复触发，不遮挡操作。

Mac 菜单栏下拉/主窗口的设备状态行显示「Brick · 95%」及充电标记；断连显示「上次 95%」或未知，不给陈旧数据实时样式。菜单栏图标无需常驻新增多项文字。

低电量不强制切断蓝牙或改变用户待机模式。沿用系统关机保护；当前快速待机会暂停系统监控进程，因此在补充通知前必须审查低电量保护是否仍有效，必要时先调整监控暂停策略。不能用界面上的电量显示代替电源保护。

## 6. 待机与消息提醒

后台接收、通知去重、灯光/震动、电量采样由 Go 服务负责，不依赖已经暂停的 PocketJS 渲染循环/原生状态轮询。息屏关闭麦克风，不持续录音；蓝牙连接保留。

| 事件 | 默认提醒 | 界面文字 |
|---|---|---|
| 一轮正常完成 | 顶部灯条主题色闪 3 次＋短震 2 次 | 本轮回复完成 |
| 等待用户回应 | 琥珀色慢闪 3 次＋短震 1 次 | 需要你回应 |
| 失败 | 红色闪 2 次＋较长短震 1 次 | 执行失败 |
| 用户主动中断 | 不提醒 | 已中断 |

闪灯总时长约 2–3s、每秒不超过 2 次；震动起点为两次 60ms，间隔 120ms，强度在实机校准。录音中暂缓机械震动直到录音结束。可分别关闭任务灯光/震动，普通按键触感继续跟随系统设置。

提醒不自动亮屏、不自动切模式、不抢 Mac 焦点；主界面角落显示未读数，Y 进入任务列表后查看。当前选中任务的状态变化可直接回显，其他任务不打断录音。

默认订阅从 Brick 发送过消息的任务和用户显式关注的任务，选择任务即关注；仅打开任务列表不关注所有历史任务。事件以 taskId + turnId + eventId 去重。完成表示一轮回复结束，不推断整个项目已完成。

Mac 接收事件后先保存未读摘要，再通过 BLE 推送；Brick 确认收到后不重复震动。断线期间累积消息，打开应用或重连补快照：保留未读列表，静默确认送达，不震动或闪灯。保持蓝牙连接的息屏待机仍实时提醒。Mac 睡眠/退出期间不能保证及时接收；系统深度休眠/Brick 关机期间不能及时闪灯。

LED 分区接口已确认，优先复用内核 `effect_*` 的颜色、次数和速度，不依赖连续逐帧写灯。震动接口已确认存在；此次设计阶段没有实际触发电机或灯光。运行前保存被修改分区的参数，提醒结束/服务退出恢复，不覆盖低电量指示，不启动第二个争抢灯光的常驻程序。

## 7. Mac 端责任与控制接入边界

Mac 负责百炼识别、目标定位、输入/编辑/发送、Codex 能力检测、任务状态接入以及离线通知队列。继续使用正式安装的 `/Applications/Brick Mic.app`，不让用户给原型或多个开发副本重复配置权限。

普通模式仍检查本次前台应用与可编辑焦点。Codex 模式允许主动激活选中任务，使用独立目标定位策略；不能直接删除现有普通模式的前台保护。

任务定位使用官方支持的 `codex://threads/<thread-id>`，但链接只证明能打开任务，不能证明输入框已经聚焦。可靠读取目标任务、定位可编辑元素和加载结束检测是实施前置验证项。

任务列表/完成状态优先使用受支持的事件或插件接口。官方 App Server 提供 thread/list、turn/start 和 turn/completed，但独立启动 CLI App Server 不能视为自动接管桌面应用现有线程。此前检查本机默认共享控制 socket 不存在；需验证本版本桌面适配方式。

Hooks 可提供会话生命周期/结束通知，但不等于历史任务列表、任意任务定向发送接口。相关 Hook 必须正常经过 Codex 的信任机制。不能依赖私有数据库或解析未承诺稳定的 transcript 格式作为首版控制协议。

若不能可靠得到任务 ID、确认目标输入框或读取必要状态，Codex 控制能力维持未就绪，普通语音功能正常使用；不能用固定坐标点击伪装为可靠的任务控制。首个实施阶段要先走通两条真实桌面任务的定位与输入闭环。

## 8. 通信与响应时间

保留现有音频帧和流式上传路径，不增加录音后整段传输、额外 LLM 文本润色或每次全量任务历史拉取。

协议升级通过 hello 协商版本与能力，旧客户端继续基本语音输入。新增逻辑消息：

- capabilities：Codex 运行/适配就绪、可支持的编辑动作、发送能力。
- mode/select 与 task/select：模式、任务及当前绑定版本。
- edit：方向、删除/菜单动作、选字标志、目标版本、短有效期。
- submit：目标任务、请求 ID；幂等并明确区分未提交/已确认/结果不确定。
- target/status：定位中/已就绪/失败；当前目标展示信息。
- task/page 与 task/delta：分页摘要和增量状态。
- notification/ack：事件及接收确认。
- battery：百分比、充电状态、采样时间与有效性。

消息统一携带协议版本、连接代次和请求序号；输入/识别另带录音会话 ID。任何模式/任务变化让旧目标版本失效。编辑操作不重放；提交结果不确定时不自动重试，防止重复消息。

BLE 按实际协商 MTU 分片，不能直接把大 JSON 塞进现有控制写入特征。实时录音优先，关键取消与确认及时处理，任务摘要在录音时限制/合并，电量低频推送。列表首屏加载后即可选择，不等待全部任务。

性能目标是待验证的验收指标：缓存目标的按键到 Mac 编辑反馈 P95 < 100ms；息屏唤醒仍保持现有快速路径；BLE 控制扩展不明显增加音频积压。冷启动/任务加载/云端收尾分开计时，不能用模拟原型的动画延迟承诺实机性能。

扩大到桌面控制前明确绑定用户的 Mac 接收端；协议校验接收端、连接代次、目标和权限，生产控制需完成配对/绑定验证。普通录音数据不因设计原型而新增持久保存。

## 9. 实施顺序与验收

### 第一批：电量、模式和桌面输入可行性

实现常驻电量/充电、Mac 电量回传、完整物理按键映射、模式状态、START 返回普通。并验证真实 Codex 两个任务之间切换、聚焦正文输入框、从其他 Mac 应用定位回来。

重点验收：十字键/肩键/B 作用于 Mac；模式与列表不会混用按键；普通模式不激活 Codex；Codex 模式从其他前台应用定位到指定任务；任务不匹配时停止输入。

### 第二批：任务输入与掌机提交

选任务、定向识别填入、编辑菜单、X 幂等发送、目标失效恢复；恢复上次任务。允许未发送内容留在不同任务的 Mac 输入框中。

验收：录音结束只填入，按 X 才发送；任务切换不串字；返回普通不提交也不清空；取消后迟到识别不输入；Mac 已有选区时语音替换；任务运行时提交行为按 Codex 实际支持的追加/排队规则显示。

### 第三批：后台通知与稳定性

接入任务事件、后台 LED/震动、未读摘要、断线补同步、息屏电量采样与电源保护；整理 Mac 设备状态。

验收矩阵：普通/Codex × 亮屏/息屏 × 连接/断线；完成/待回应/失败/中断；低电量/充电/未知；Mac 手动切应用或切线程；Codex 退出；模式切换时有未发送文字；长按时断线不持续删除；服务退出灯光恢复；重新开机恢复模式且不自动发送。

自动化完成状态机、协议和模拟 UI 验证后，整包实机验证，避免每个小按钮单独要求用户插卡测试。只将必须用户感知的录音、手感、灯光、震动及电源行为交给集中实测。
