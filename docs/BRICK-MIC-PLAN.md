# Brick Mic 实施计划

分支：`codex/brick-mic`。

目标：Brick 内置麦克风 → 蓝牙 → Mac → 百炼实时 ASR → 当前文本框。

新增设计：[语音输入与 Codex 控制完整方案](BRICK-MIC-CONTROL-DESIGN.md)，含两种模式、Mac 光标编辑、任务定位、掌机提交、息屏通知和电量显示。当前实现分支为 `codex/brick-mic-control`；协议、原生输入和提醒已实现并编译，真实 Codex 输入框适配待验收。

## 阶段与验收

1. 硬件与蓝牙：确认 ALSA 录音通道、BLE 外设能力；Mac 能发现并连接，接收完整音频帧。
2. 完整语音输入：掌机按住 A 录音，松开结束；B 取消；录音时实时上传，Mac 一次显示完整文字并可自动输入最终结果。
3. 可选系统麦克风：另行实现 CoreAudio 虚拟输入设备。本阶段不混入语音输入首版。

## 数据格式

所有整数均为小端。通知分片头为 9 字节：类型 u8、会话 u16、帧序号 u16、分片偏移 u16、消息长度 u16。

- 类型 1：开始消息 JSON，含 16kHz、IMA ADPCM、协议版本。
- 类型 2：音频。帧内头为样本数 u16、首样本 i16、步长索引 u8，随后低位优先的 4bit IMA ADPCM。
- 类型 3：结束消息 JSON，含总帧数与样本数。
- 类型 4：取消。
- 类型 5：错误。

每帧 20ms（320 样本），独立解码状态；握手后按 ATT 容量分片。Mac 对分片连续性、帧序号、结束帧统计进行校验，任何失败都不自动输入。

控制特征只接受 hello、ack、result、append、error。ack 只接受当前接收端、当前会话、不超过已发送帧数且单调递增的进度。不会提供远端开启麦克风指令。Mac 按字符边界分片回传结果，掌机显示最终文本。

## 运行边界

首版 BLE 尚不强制配对，后续以掌机确认接收端并加密连接完善。Mac 按用户要求直接从 shell 配置读取 Key，设置写入 `~/.zshrc` 的 `DASHSCOPE_API_KEY`；不再读取钥匙串。默认不自动输入，辅助功能权限由用户开启。仅最终结果显示并输入，断线和取消停止识别。
