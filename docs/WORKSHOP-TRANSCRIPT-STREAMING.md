# 游戏生成器：对话排版与流式输出

本轮完成并 SSH 部署到 TrimUI Brick。

## 问题与修改

- 照片中的“文本过长”来自工坊原生消息排版的 1,024 行上限。工具校验错误带有大量 Received arguments，触发上限；不是生成游戏的 PICO-8 文本限制。现在默认显示错误原因，SE 详情分页读取完整内容。
- 原来每次更新遍历并排版整份历史，长会话会越来越慢。现在增量维护消息索引，只排版可见片段，缓存有明确预算；首页使用轻量项目信息，打开项目才加载完整历史。
- 正文行距缩为 44px，段间空白 12px。状态和大消息计数分配独立宽度，底部无重叠；继续使用系统颜色变量。
- 正常生成使用真实 SSE：中文跨网络块拼接，文字提前显示，约 180ms 合并一次排版。浏览旧记录不跳回底部；右键回最新。工具参数完整后执行，中断/取消残缺调用不会执行，已收到文字保存。摘要保留完整响应方式。

## 验证

真实 ARM64 / Solid / QuickJS / 原生字形与渲染器，隔离项目，不使用付费模型：

- 10,003 条消息，2,058,717 字节项目，单条 22,000 行回复及 1,800 行错误：通过完整分页与首尾导航。
- 进入对话约 349ms（应用已启动）；20 次翻页平均 31.6ms，峰值 120.1ms。重复缓存页面无新增排版任务。不是网络延迟或游戏运行性能测量。
- 慢速本地 SSE 经 SSH 转发到掌机：模型 HTTP 完成前文字可见，约 634ms 观测窗口只提交 4 次布局；真实 Pi 五工具发布链路通过。
- 手柄翻页、详情、封面优先级、长按删除、Start 试玩、语音提交/取消，以及 Agent 编辑/摘要/素材/模型回归通过。
- 测试前后现有卡带哈希保持 f640eec324a1a32bf26ced4a742bc208898ccde191a4e8873f48ecc548a5d72c。

## 边界

项目文件上限 4MiB，HTTP 响应上限 1MiB。完整历史仍在打开项目时读入；本轮解决的是随每次更新重复排版全历史的问题，未实现磁盘级无限历史。小正文缓存最多 24 条/131,072 字符，分页最多 64 个窗口，另保留一条大消息。
