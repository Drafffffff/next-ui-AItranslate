# 试玩返回：最后一页缓存

试玩会退出工坊进程，游戏退出后 launcher 用 `POCKETJS_WORKSHOP_RESUME=1` 重新启动工坊。之前必须先加载项目列表、完整项目 JSON、字体和末页排版才能显示结果。

现在按 SR 试玩前，先保存游戏，再把对话普通视图的最后一页存入 `project-info/<id>.json` 的 `returnView`。返回时优先读取这个小文件，准备该页字体并显示已排版的文字；至少绘制一帧后再读取完整项目。完整对话、发布恢复、项目列表和其他封面随后恢复。普通启动继续进入项目列表。

缓存不进入模型上下文，不替代原始历史，不截短项目文件。完整项目恢复前不能发送语音需求或开始试玩。缓存绑定项目 ID、版本、更新时间、布局版本；native 项目保存会先删除索引，随后重建，不会沿用过期页面。待发布或待回答问题不生成返回缓存；缓存缺失、损坏或不兼容时走正常恢复。最多 24 行、468px，内容和格式均经过验证。

## 掌机测量（2026-10-02）

在 `nextui-brick` 上运行 ARM 原生宿主，使用真实塞尔达项目的离线副本及 80,003 条消息、约 11MB 的压力项目。每个项目交替测旧 JS 与新 JS 三次，使用相同 native 宿主、字体、SD 卡和无模型凭据配置。表中为三次中位数，无截图写盘干扰。

| 项目 | 之前显示末页 | 缓存显示末页 | 首屏缩短 | 完整恢复：之前 / 现在 |
| --- | ---: | ---: | ---: | ---: |
| 塞尔达，50 条消息 | 1,697ms | 1,446ms | 15% | 1,700 / 1,729ms |
| 压力项目，80,003 条消息 | 4,044ms | 1,412ms | 65% | 4,049 / 4,064ms |

指标从 native 开始读取 JS/Pak 到末页显示，包含 QuickJS 启动、字体和显示所需项目处理，不包括游戏退出、进程创建和此前 SDL 初始化。没有清除系统文件缓存，也不是完整游戏退出到可操作的端到端测量。原进程仍会重新启动：首屏提前，完整历史恢复的总耗时基本持平。超长 JSON 解析仍在 JS 线程执行，期间暂时不能交互。压力项目新版本的峰值 RSS 为 89,284KiB（约 87MiB），无需常驻另一份完整 Agent。

## 验证

- `npm run verify`：所有原有验证及返回缓存验证通过，包括保存失效、布局/版本/内容验证、只读轻量元数据、损坏/缺失兜底。
- `verify-return.py`：真实项目、超长对话，验证缓存先于完整历史解析显示；错误版本、错误布局、损坏和缺失缓存都恢复成功；最后一页不覆盖底部快捷键。
- `verify-experience.py`：原生控制器、翻页、工具详情、语音归属与取消回归通过。
- ARM 同一历史和 ROM 在旧版/新版返回及三次计时之后 SHA-256 一致；测试只操作独立副本，没有调用模型或修改用户游戏。

测量与截图保存在 `build/workshop-return-2026-10-02/`。部署后需在新版中试玩一次以生成缓存；由旧版本启动的试玩没有预先缓存，首次返回会使用正常恢复。
