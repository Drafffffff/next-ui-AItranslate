# 游戏生成器：至少十轮评测与迭代

目标：使用现有生产 Agent 评测链路建立可复用评测集，至少执行十轮真实模型测试，以失败证据持续修正提示词和 harness。旧任务的测试不计入这十轮。

真实模型使用掌机现有 DeepSeek Flash 渠道；Mac/掌机共享 PocketJS、QuickJS、Pi、提示词和工具。每轮最多四个独立原生进程并行。掌机配置与现有游戏不作为可写测试夹具。

评测集：`ports/pocketjs-brick/workshop/eval/iteration-cases.json`。轮次与产物：`build/workshop-eval/campaign-2026-10-02/campaign.json` 和对应 `rounds/` 目录。

## 验收口径

- 至少十轮完成的真实模型评测，保留请求、冻结源码/Skill 哈希、工具轨迹、实际产物及严格 VM 回放。
- 每轮复核客观检查的适用范围，记录失败分类、源码依据、修正或保持原方案的理由，执行对应回归。基础设施失败、fixture 和重新评分不冒充真实模型轮次。
- 覆盖平台、网格、落块、赛车、战斗、3D；覆盖新建、精确修改、素材保留、音乐、连续项目修改和讨论/提问语义。
- 提示词和 harness 的改动均有问题依据和验证；不会为了凑轮次无理由增加约束。
- 最终汇总可打开的 HTML 报告、各轮趋势和未解决问题。比较通过率时使用相同案例/断言版本；模型代码审阅单独呈现，不视为实际试玩。
- 最终版本检查应用回归、严格断言的负向控制、Mac/ARM 同源码一致性；仅部署经过验证的版本，保留现有用户项目。

## 轮次安排

下面是覆盖方向，具体案例和改动由上一轮证据调整。

| 轮次 | 重点 |
| --- | --- |
| 1 | 平台、赛车、Boss、3D 新建基线 |
| 2 | 基线中失败机制的针对性修复与强断言 |
| 3 | 网格/落块的首次、持续与严格单次输入 |
| 4 | 局部修改、素材保留与音乐修改 |
| 5 | 连续项目迭代和设计记录一致性 |
| 6 | 讨论、真实提问与用户回答后的动作语义 |
| 7 | 生命周期、目标可达与恢复边界 |
| 8 | 长会话/压缩、工具失败后的恢复与发布门禁 |
| 9 | 未见场景、更多反馈形式与回归缺口 |
| 10 | 同规则复测、最终跨类型回归与 ARM 一致性 |

执行记录在每轮结束后追加；当前状态以 campaign.json 与原始 run/summary.json 为准。
