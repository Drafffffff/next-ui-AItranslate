# 游戏生成器 Harness 与掌机体验验收

2026-10-02；已通过 SSH 部署到 `nextui-brick`。本轮测试使用隔离项目和模拟模型/ASR接口；没有把开发测试当作用户游戏的自动玩法验证。

## 已交付

- 一个项目、同一游戏入口：新建立即保存并发布第0版基础脚手架，含标题、方向键移动、结束和重开。首个Agent发布仍为第1版；启动恢复可完成被打断的初始化。
- Pi真实工具循环增加`ask_user_question`：关键玩法决策可给建议选项，短A选择、长A语音自由回答、↑↓选择、B跳过、SE完整详情；执行中X停止，取消后可以B返回列表，重进项目再答；不会因为返回而自动替用户跳过问题。待回答问题及已经收到但还未配对提交的回答持久化，重开可继续。保存回答期间保持忙碌状态，避免重复提交。问题和实际回答直接显示在会话记录中。纯玩法讨论可以结束，无需虚构新游戏版本。
- 核心PICO8 Skill加入玩法共创；新`gameplay-design`模块把动作、目标、风险取舍与反馈落到可玩的规则，提供地牢、赛车、解谜、节奏平台、钓鱼与第一人称探索设计练习。它们明确标记为设计练习，不冒充社区原作。音乐依旧单独渐进加载，社区素材与许可证哈希保持验证。
- NextUI封面对应ROM basename：选中的封面/首帧同步到`Roms/AI生成游戏 (P8)/.media/<id>.png`。实际五个游戏均已补齐，字节与应用封面来源一致。更新卡带失效旧首帧/菜单图，删除清理两处图片；同一项目更新缩略图会释放旧纹理。
- 固定模型目录新增百炼`deepseek-v4.1-flash`，合计五个选项，每屏四行滚动。切换保留原渠道密钥/地域、ASR设置和其他配置，不在掌机查询目录。[百炼官方模型页](https://help.aliyun.com/zh/model-studio/deepseek-v4-1-flash)。
- 首页和会话使用同一bloub头像；等待用户回答时idle。移除旧空态保存句子，补齐新选项中文字形。沿用系统颜色、Brick Mic底栏和SR标签。
- SSE真流式输出仍启用：文字在HTTP结束前显示；完整工具参数收到后才执行，取消不提交不完整参数。对话仅排版可见窗口，保留完整原文，分页缓存有界。

## 上下文与资源范围

用户指定的上下文窗口是**500,000 token**。生成输出预算为32,768 token，因此默认预留至少32,768，约467,232 token触发压缩，保留约12,000 token近期记录；估算还包括Skill/工具声明和中文文本，并非准确的账单token数。

摘要输出单独默认4,096 token；只有截断时自动提高额度重试一次，最多8,192。空摘要、鉴权、网络、取消和保存失败不会覆盖原始历史，不反复请求同一失败。完整会话始终保存在项目中。

连续开发默认允许1,000轮模型调用，显式配置的适配器预算可至10,000；X中断仍有效。生成输出由原先10,000扩大到32,768 token。宿主请求/卡带8 MiB、响应16 MiB、项目16 MiB、工具参数8 MiB、字形8192；响应缓冲按需增长。普通请求默认120秒，配置可延长到600秒。保留的是能明确报错的内存/传输预算，不以这些数字宣称硬件物理极限或所有输入永远无崩溃。

## 性能证据

| 同一隔离压力项目 | Mac原生运行时 | TrimUI Brick ARM64 |
| --- | ---: | ---: |
| 消息总数 | 80,003 | 80,003 |
| 完整项目文件 | 11,241,252 bytes | 同一文件 |
| 单条回复/工具错误 | 22,000行源码块 / 1,800行错误 | 同一内容 |
| 打开并准备首个对话窗口 | 257 ms | 2,128 ms |
| 缓存后的平均翻页 | 6.4 ms | 30.4 ms |
| 缓存后的峰值翻页 | 7.8 ms | 33.9 ms |
| 进程峰值RSS | 143 MiB | 102 MiB |

在Brick上，这一压力区间能保持滚动可用，没有崩溃；首次打开大文件仍需约2秒，完整JSON解析与索引集中在打开阶段。它验证了当前实现的实际压力区间，**不是故意耗尽RAM测得的硬件最大值**。缓存后JS文字排版调用无增长；原生文字/图集计数工具目前返回0，因此不把其0值当作性能证明。完整历史与ROM哈希在查看压力项目前后相同。

## 验证记录

- `npm run verify --prefix ports/pocketjs-brick/workshop`：真实Pi流程、默认/显式轮数、流式、Markdown与长文本、五模型/密钥隔离、默认Skill/模块、压缩、精确草稿检查后发布、编辑算法、音频保留和问答持久化。
- `npm run verify:quickjs --prefix ports/pocketjs-brick/workshop`：锁定QuickJS，256 KiB栈/32 MiB堆测试环境，5000头像帧、Pi工具、上下文压缩；最终活跃堆约2.65 MiB。这个32 MiB是隔离测试额度，不是掌机运行时的上下文容量。
- 原生`verify.py --recover`：新建脚手架、唯一ROM、重开修改、真实操作记录、菜单名称与发布恢复。
- 原生`verify-experience.py`：封面优先/首帧回退与`.media`字节同步、列表、翻页、详情、录音取消、模拟识别结果发送、SR试玩、Y删除进度与恢复。
- 原生`verify-question-ui.py`：短A选择、长A语音、断电重开，同一问题只有一个实际回答，脚手架→第1版，底栏无覆盖；截图人工检查并修复中文选项缺字。
- 锁定z8lua解释器实际执行脚手架：标题/开始、方向移动/边界、结束冻结、重开、返回标题。
- Brick实际Pi+curl+SSE：收到文字时HTTP仍未结束，继续完成发布；无云端额度消耗。
- Brick实际问答：持久等待→关闭进程→重开→手柄真实回答→Pi发布；真实fake-08生成脚手架首帧和菜单图；五模型保存/重启持久化。

ARM问答验收曾因测试程序在保存答案和下一轮请求之间误判空闲而提前退出，取消curl请求；修正为等待发布版本与最终空闲。产品同时增加保存回答期间的忙碌状态。修复后完整ARM流程通过，未改用户游戏或配置。
