## 已实施的行为

- 默认 PICO-8 Skill：将输入重复间隔、绘制工作量、素材休止、音效重触发与运行器问题分开。以当前草稿和实际发布源码为依据，每轮定位一个主要因素；保留操作、目标和素材。缺少实测不宣称 CPU 不足、音频欠载或完全解决。
- 输入模块：新增 `assets/snippets/grid-input.lua`，按需加载到 `grid-turns`；首按/换方向即时响应，长按在第 1/7/10/13 帧提交，松开清理、相反方向取消。确认、重开、旋转与硬降用严格边沿。完整推箱子教学示例采用同一组件。
- 音乐模块：继续渐进加载；按锁定核心的 183 samples/unit 核对音长与 tempo，区分延音、断奏与休止。事件音效使用独立短槽位和成功事件触发，BGM 不被每帧重启。保留社区素材及署名，不全量改写曲目。
- 绘制和碰撞：危险画面与碰撞范围一致；成长型网格用占用索引；3D 缓存帧内相机数据、限制可见对象和排序规模，明确 spr 格数与缩放的区别。这些是实现指导，不是性能达标证据。
- 发布诊断：长音效与 BGM 共用槽位会提示检查事件节拍；未绑定的普通 Lua `table/math/string` 标准库调用阻止交付。自定义同名对象仅提示作用域复核，评论/字符串/嵌套字段不误判。升级 validator 标记，使旧检查证据失效并重新检查。

## 补充发现：软降与回放误报

第二轮 v4 两路生成原报告均通过；源码复核发现俄罗斯方块只在旧重力倒计时结束后应用软降间隔，因此首按仍有较长等待。补充模块约束：软降立即生效，使用独立计时或立即截断旧重力等待；正常重力与软降同帧不重复结算。

新增首按下落断言后，旧评测器仍错误报告通过。核对锁定核心发现 P8 assert 只绘制失败并停止卡带，不抛普通 Lua 异常；单看 ExecuteLua 返回成功不代表规则为真。开发回放器现临时安装严格测试断言、独立读取失败标志，并在异常后恢复卡带原接口；加入故意 assert(false) 必须判失败、下一条 assert(true) 恢复正常的负向回归。此修改仅作用于 Mac 开发评测，不替换掌机游戏的 P8 API。

因此 v4 的旧规则断言不作为验收证据；原始生成和旧报告保留用于定位问题。最新真实生成、部署和文件校验结果在执行结束后追加。
