# NextUI + 游戏内 AI 画面翻译

**仅适配 NextUI。** 这是 NextUI 游戏内的扩展功能，不是通用模拟器插件；不适配原厂系统、MinUI、CrossMix 或其他固件。

默认热键为 **MENU+X**：在游戏中按住 MENU，再按 X，即可翻译，无需先手动绑定。需要联网并配置自己的模型 API Key。

在游戏里按一个热键：抓下当前画面 → 发给多模态模型翻译 → **把译文贴回原文所在的位置**。

当前编译版本基于 **NextUI v6.14.0（20260719）**，目标平台为 **tg5040**；其他 NextUI 版本或平台尚未验证，请勿直接替换程序。AI 翻译改动位于 `minarch.elf`；启用下面的拼音目录功能时，还需要一起更新 `nextui.elf`。


## 拼音目录与退出自动存档（2026-09-30）

- 普通目录和游戏列表按显示名称的完整拼音排序，中英文共用 A–Z 顺序；`map.txt` 中的中文别名同样有效。
- L/R 字母跳转按拼音首字母分组。最近游玩、手工合集保留原有的专用顺序/跳转规则。
- 拼音在本地生成并缓存，覆盖 41923 个汉字及 3437 个多音词词组，支持简繁体，不联网。
  词库未覆盖的多音专名按单字默认读音处理；无法转写的文字保留原字节顺序。
- 游戏菜单选择 **Quit**，成功写入隐藏的退出存档槽（内部编号 8）后退出；手动槽 1–8 不覆盖。
  下次普通打开游戏会恢复这个退出存档，Resume 和预览也指向本次保存；多碟游戏恢复对应光盘。
- 写入使用临时文件替换，保存失败保留上一份存档。失败、模拟核心不支持或成就 Hardcore 模式禁止存档时，
  提供返回菜单和明确选择不保存退出两个选项。休眠存档仍使用原来的独立槽。

构建产物：`workspace/all/nextui/build/tg5040/nextui.elf`、`workspace/all/minarch/build/tg5040/minarch.elf`。
拼音表由 `tools/generate-pinyin.py` 生成，生成时依赖 `pypinyin==0.55.0`；运行与设备编译不依赖 Python。
词库许可见 `workspace/all/nextui/PINYIN-LICENSE.txt`。

## AI 截图隔离显示 Overlay（2026-09-30）

翻译请求直接从视频模块持有的模拟器原始帧生成截图，按当前游戏矩形进行裁剪和缩放，
保持黑边、宽高比及画面偏移。游戏边框 Overlay、上一轮译文、通知和性能 HUD 不进入模型；
不再依赖对最终 GL 显示缓冲区截图，也不靠提示词猜测哪些文字属于 Overlay。
扫描线、边框和显示着色器效果不叠加到模型输入，减少附加文字和图像处理对识别的干扰。

原始帧缓冲区与性能 HUD 分离。通常只在请求截图时创建独立快照，不增加普通帧的复制、
磁盘缓存或模型调用；仅开启性能 HUD 时使用显示专用副本。
AI 帮你玩的截图也使用相同的原始游戏帧，避免识别自己的状态角标。
没有有效游戏帧时报告抓帧失败，避免退回包含 UI 的屏幕截图。

实际 SDL2 像素验证（含 RGB565/XRGB8888、行距、HUD 污染、重复帧、裁剪/比例/偏移和生命周期）：
```bash
python3 tools/测试干净游戏截图.py
```
需要本机 SDL2 和 pkg-config；也可用 `--source 输出.c` 导出测试源码，在 SDL2 工具链中编译运行。


## 当前显示方案：粗描边文字 Overlay（2026-09-30）

完整保留游戏画面和原文，译文作为独立文字浮层显示；**不擦原文、不生成背景框或半透明底板**。
每个字使用约字号 **1/5** 的不透明描边。以 **720 高画布**为基准，最小字号 **32px**，正文目标 **40px**，
标题上限 **72px**；随 framebuffer 高度缩放（768 高分别为 35 / 42 / 76px）。
最小字号是硬下限，空间不足优先扩展短标签/增加行数，不再偷偷缩回 8px。
对白顶端对齐，标题/菜单沿用居中锚点；行距容纳描边，浮层按就近位置避让，底部连续版权说明合并。
极密集画面仍可能因为可用空间不足发生移位，不能保证每一项都和原文重合。

配色保留原文色相：暖白/蓝黑、青色/深海蓝、金黄/深棕、珊瑚红/深酒红、浅蓝/靛蓝、浅绿/墨绿等。
黑字使用奶油色描边和一像素暗外轮廓。8 组文字/描边配色按 sRGB 相对亮度计算，
对比度 **7.58:1–16.87:1**，全部超过 [WCAG 2.2 AAA 普通文字 7:1](https://www.w3.org/WAI/WCAG22/Understanding/contrast-enhanced.html)。
此结论只针对指定的字色/不透明描边色，**不是整个游戏画面的 AAA 认证**。
修改调色板后运行 `python3 tools/检查翻译配色.py`；测试直接读取 C 中的 RGB 值，阈值判断不四舍五入。

提示词新增 `kind`（dialogue/menu/title/label/caption），要求自然紧凑的游戏用语、忠于原作语气、
保留强调色与对齐方式，连续版权说明合成一段。旧响应缺少 kind 时仍可渲染。
三张新提示词实测图为 City Connection、Lolo 3 和 Darkman 剧情页；其余预览复用旧缓存，
不能把旧缓存预览当作新提示词的翻译质量验证。

修复了字号降到下限时先释放字体再退出、导致整条译文消失的问题。截图预览直接提取并运行
`ma_ai.c` 的 SDL 渲染代码，使用缓存响应和设备字体，无需请求 API：

```bash
python3 tools/预览翻译.py 原图.png 缓存响应.json 字体.ttf 输出.png
./tools/测试解析器.sh
```

预览工具需要 SDL2 / SDL2_image / SDL2_ttf 开发库及 pkg-config。原文仍可在译文周围看到，
这是 Overlay 的预期行为；模型坐标偏差仍可能影响浮层位置。
后文「改版一～三」保留为历史实验记录，其中擦除/底板方案已被本方案替代。

## 怎么用

### 1. 装

```bash
./部署到卡上.sh
```

脚本会自动找卡、备份原 `minarch.elf`、替换成新的。

### 2. 填 API key

**Key 放在公共文件**：卡上 `.userdata/shared/ai-keys.txt`。

```ini
DEEPSEEK_API_KEY=你的DeepSeekKey
DASHSCOPE_API_KEY=你的百炼Key
```

两项可并存；请求时优先读取对应公共 Key，没有填写时兼容旧 `aiDeepseekKey`、`aiBailianKey`、`aiApiKey`。修改公共文件后，下次请求生效。

**翻译设置**仍在 `.userdata/shared/ai-translate.txt`：

```
# 服务商：0=百炼 Qwen3-VL   1=DeepSeek(默认)   2=自定义
aiProvider=1

# 仅 aiProvider=2 时用到
aiEndpoint=https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions
aiModel=qwen3-vl-plus

aiTargetLang=简体中文
aiHoldSecs=5
aiMaxImageWidth=768
aiTimeoutSecs=20
aiDebug=0
```

**开关 / 服务商 / 译文停留 / 送图宽度 / 调试信息 也能在游戏里改**：`Menu → Options → AI Translate`。
改完直接写回这个文件（注释和其它行都保留），不用拔卡。

**默认服务商是 DeepSeek**（`aiProvider=1`）。它的坐标定位不如百炼稳，译文可能贴歪；
不满意就在游戏菜单里切回「百炼 Qwen3-VL」。

> **为什么不用 `minuisettings.txt`？**（踩过的坑，别改回去）
> `CFG_sync()` 会按调用者**自己的内存结构**把整个 `minuisettings.txt` 重写一遍。
> 卡上的 `nextui.elf`（启动器）和 `settings.elf` 还是原版、不认识 `ai*` 键，
> 于是**每次开机启动器都会把 ai 那几行抹掉**——实测：写进去 8 行，开机后剩 0 行。
> 放独立文件后只有本模块读它，谁也动不了。

### DeepSeek 能不能用？

能选，**快得多（0.9~1.4s，百炼要 5~8s）、读字很准**，坐标在改成 0~1 归一化之后
实测也基本准了（三张真实画面，换算误差 2~5%，全部落在 0~1 内）。但仍有一个模型侧的
老毛病：**它的坐标比例会随送图尺寸变** —— 同一张图，384 宽送进去它给的第一行 y 是真值的
一半（300 vs 671），768/960 宽送进去又对了。所以换个 `aiMaxImageWidth`、换张图，
有可能又整体歪一档（这是它内部缩放画布造成的，提示词和本地换算都管不了）。
结论：**想快选它、想稳选百炼**。默认仍是百炼。

### 3. 默认热键：MENU+X

完成安装和 API Key 配置后，进入游戏，**按住 MENU，再按 X** 即可翻译。
所有模拟器机种共用这个内置默认值，首次使用无需逐个机种绑定；只按 X 仍是游戏按键。

如需修改：进入 **Menu → Options → Shortcuts → AI Translate**，按 A 后设置新的组合键，
再到 **Options → Save Changes → Saved for console** 保存到当前机种。

已有机种或单个游戏的 `AI Translate` 自定义绑定会优先使用，包括曾保存的 `NONE`（关闭热键）。
如果 MENU+X 没有反应，在上述菜单检查绑定，同时检查是否有其他快捷键占用了 MENU+X。
默认绑定直接内置于程序，不需要向模拟器 pak 的 `default.cfg` 添加 `bind` 行。

### 4. AI 帮你玩（自动代打）

另配一个热键（同上，Options → Shortcuts → **"AI Auto Play"**，建议 `MENU+Y`）。
游戏中按下后它会循环：

```
抓帧 -> 问模型「这一帧该按哪个键」-> 注入按键 -> 等 0.5 秒 -> 再来
```

画面左下角会显示状态角标（已运行时长 / 第几次 / 最近动作 / 按任意键停止）。
**按任意键退出**，到次数上限也会自动停。

**上下文与"长期动机"**：模型每轮都会返回一个**长期目标**（`goal`）和一句**本次理由**（`note`）。
`goal` 会一直沿用，`note` 进一个最近 8 条的环形缓冲，两个都落盘到
`.userdata/ai/play-memory.txt` —— 所以**跨会话也记得自己在干什么**，不是每帧从零开始反应。

**⚠ 两个现实约束**：

1. **慢**。一轮要 1~2 秒（模型推理本身），所以只适合**回合制/慢节奏**游戏
   （RPG 对话、走迷宫、菜单操作）。动作游戏跟不上 —— 这是 API 往返延迟决定的，优化不掉。
2. **花钱**。每次决策都是一次带图的 API 调用。按 DeepSeek 单价约 $0.0002/次，
   默认上限 500 次 ≈ 25 分钟 ≈ $0.1。上限在配置里：`aiPlayMaxCalls`。
   进度条角标上的"第 N 次"就是实时用量。

配置（写在 `.userdata/shared/ai-translate.txt`）：

```
aiPlayIntervalMs=500    # 两次决策之间的等待，一轮 = 请求耗时 + 这个
aiPlayMaxCalls=500      # 单次会话上限，防烧钱
```

### 5. 用

`Options → AI Translate` 有 **8 项**：AI 翻译 / 服务商 / 译文停留 / 送图宽度 / 调试信息 /
状态角标 / **上下文** / **清空当前场景**。

游戏里按下热键 → 画面冻住显示"翻译中…"（约 5~8 秒）→ 译文贴在原文位置。
译文**默认保留 5 秒后自动渐隐**（400ms 交叉淡出），中途按任意键可以立刻开始渐隐。
想让它一直留到你按键，把 `aiHoldSecs` 设成 `0`。

译文出现时**不再显示底部「按任意键继续（N 秒后自动）」提示条**（2026-09-30 按需求移除，
那行黑底药丸会盖住画面下部）。提前结束与自动渐隐的行为完全不变，只是没有可见提示。

**支持所有机种**：FC / SFC / MD / GBA / GB / GBC / PCE / PS / SGB / 街机……全都行。
因为热键和覆盖层都在 `minarch` 里，和具体模拟器核心无关 —— 已核对发行包里
30+ 个 `*.pak/launch.sh` 每一个都是启动 `minarch.elf`。
模型看到的是缩放后的整屏画面，所以坐标映射与游戏原始分辨率无关。

### 模型怎么选（实测数据）

同一张章节标题图，各测两次：

| 模型 | 往返 | y 坐标误差 | 结论 |
| --- | --- | --- | --- |
| **qwen3-vl-plus** | 7.4~8.0s | Δ −4~−2 px | **默认**，框最紧 → 字号正常、不漏译 |
| qwen3-vl-flash | 4.3~5.6s | Δ −4~+3 px | 最快，但框松（标题会被撑出底板）、偶尔漏译一条 |
| qwen3.8-flash | 32~37s | Δ −3~+2 px | 准但太慢，通用推理模型 |
| deepseek-flash | **0.9~1.4s** | 0~1 坐标下 2~5% | 快、读字准；比例会随送图尺寸变，偶尔整体歪一档 |

最后一行是 2026-09-30 改成 0~1 坐标后重测的结果：deepseek 在 384 宽的送图下
坐标已经很准（详见「提示词与排版」那节的 A/B 表），但同一张图换成 768/960 宽再送，
比例会变（真值 671 时它给 300）。**想快选 deepseek、想稳选 qwen3-vl-plus。**

## 它是怎么工作的

```
热键 → GFX_GL_screenCapture 抓当前画面
     → 缩到 aiMaxImageWidth → 存 PNG → base64
     → 拼 OpenAI 兼容的 JSON（prompt 里要求模型返回 0~1 的归一化坐标）
     → curl 子进程发出去（body 走 @文件，不走命令行）
     → 解析回 {"items":[{"orig","zh","box":[0~1],"color","align"}]}
     → 坐标统一换回 0~1000（模型若给了别的刻度也能认，见 ai_boxes_normalize）
     → 每条译文按框宽自动折行，以阅读字号为主
     → 画粗描边文字 Overlay（原图保留，无背景框）
     → 记住这一屏（原文→译文 + 模型给的进度摘要），下一屏请求时带上
     → 冻住画面等按键，然后还原
```

**本地不做任何"找文字"的图像算法**——定位完全交给模型。这是刻意的取舍：
本地找文字要求"文字外面有闭合边框"，状态条、裸标题、居中大标题全都没有框，会漏。
（那套本地检测的代码写在 `~/Downloads/ai-translate-test/overlay_v4.py`，实测能跑，但已按需求搁置。）
本地只做**排版**（折行、字号、位置与粗描边），不做文字擦除。

### 版面自适应（2026-09-30 改版三：治「遮挡很厉害」）

**问题**（用户反馈 + 8 张真实截图实测）：改版二把「一段话」合成一项之后，擦除框也从**逐行**变成
了**整块**，块内不属于文字的区域（美术、角色画、边框）被一起涂掉。逐张量「画面上被涂掉的面积」：

| 画面 | 改版二（整块擦） | 改版三（逐行擦） |
| --- | --- | --- |
| Darkman 标题菜单（文字压在美术上） | 191,858 px | **25,788 px（13%）** |
| Little Ninja 菜单（含头像） | 101,628 | **40,239** |
| Gargoyle 对话框 | 86,240 | **41,413** |
| Adventures of Lolo 3 | 81,591 | **17,126** |
| Battle of Olympus | 284,284 | 196,216 |
| Darkman 剧情页 | 322,465 | 286,951 |
| **合计（8 张）** | **1.38M px** | **0.86M px（−38%）** |

**改法（四件事）**：

1. **提示词加 `lines`**：一段话仍然只翻译一次（一个 `box` 给整块、`zh` 给整句），
   但**另给一个逐行框数组**，擦原文只擦这些行框。实测 deepseek 给 `lines` 很规矩
   （四行对话给 4 个框、菜单项各 1 个，全部落在 0~1 内）。
2. **行框收紧**（`ai_shrink_to_ink`）：模型的行框实测比字素宽 1.5~2 倍，
   在**框内部**按「偏离底色的像素」把框缩到字素范围（只缩不放，收不出来就用原框）。
   这不是"全屏找文字"，搜索范围被模型框死。
3. **底色判定**（`ai_sampled_bg` 回填众数色占比）：≥60% 算「底色纯」→ 用底色填，
   看不出补丁，还保留「往外摸边」防残字；否则算「底色杂」→ **填黑**做成字幕条观感。
   用平均色糊一块反而更难看，而且会留半截原文在色块外面。
4. **字号按原文行高封顶**（`ai_font_cap` = 行框中位数 × 0.55）：改版二会让译文撑满整个块，
   字号比原文大 2~3 倍、遮挡面积随之翻倍。0.55 这个系数是拿真机画面比出来的
   （对话框行框 54px → 30px 字高）。

**代价（要知道）**：底色杂的画面上不擦原文了，所以**原文会留在译文旁边**
（Darkman 菜单里 `HI SCORE` 的尾巴那种）。这是刻意的取舍 —— 在美术上"擦干净"
必须涂掉一大块画面，比留半截字难看得多。想彻底消除只能靠模型把行框给准。

这一轮批量跑出两个真 bug，都已修：

1. **摸边在 UI 面板上失控**：`ai_strip_is_text` 判据在「黑底 + 白色标签 + 边框」那种面板上
   每一圈都成立，四方向一路摸到上限 —— 把 Lolo 3 右侧一个 93×63 的小面板糊成 384px 宽的黑柱。
   现在**只对「横向长条」形状的行框、而且只往左右摸**（`w ≥ 2.5h`），上限 24 档降到 10 档。
   横向摸治的是「模型框比原文窄」（状态栏右边少 9%、菜单项少 25%），这是唯一站得住的场景。
2. **「底色纯度」判据用错了口径**：原来是「众数色桶占比」，白底黑字的对话框只有 0.41
   （字和边框都算进分母），会被误判成「底色杂」→ 贴黑条把白对话框涂了。
   现在改成**「离众数色 L1≤160 的像素占比 ≥ 0.50」**（= 这块地被同一种底色主导），阈值 0.50
   是在 Lolo 对话框（0.44~0.48）、Darkman 美术文字（0.56~0.65）、黑底菜单项（0.85~0.95）
   之间量出来的。

修完的效果（同一批截图，覆盖面积 / 画面改动 px）：Lolo 3 `1,165,216 → 64,368`；
Darkman 剧情页 `2,286,462 → 379,550`；面具精灵和时钟不再被擦掉。

### 连续翻译上下文：按时间保留（2026-09-30）

目标是接上连续对白的指代、人物称呼和语气，而不是让旧剧情支配新画面。

| 历史年龄 | 处理 |
| --- | --- |
| 0–59 秒 | 标记「优先承接」 |
| 60–179 秒 | 标记「弱参考」，不假定仍在同一场景 |
| ≥180 秒 | 移除对白与剧情摘要，只保留稳定译名 |

- **按屏保存**：每次成功翻译中 `kind=dialogue` 的条目作为一屏，保留原文、译文和顺序；
  没有 kind 的旧模型响应仍可兼容。菜单、状态栏、标题和版权不会占用对白记录或给摘要续期。
- **相邻屏去重**：上一屏再次出现的原文移到新屏，使用最新译文和时间，旧屏只保留未重复部分。
  整屏重复时相当于续期，不会挤满历史；更早场景重复出现同一句话仍保留其顺序。
- **时间为主，容量兜底**：最多保存 6 屏，每屏最多 32 段。上下文最多 4095 字节，优先留最新完整一屏，
  再放译名、摘要和更旧的整屏，最终按时间顺序展示对白。超预算丢整屏，不在句子中间截断。
  极端情况下最新整屏本身超过预算，只使用摘要/译名，不以残缺旧屏代替。
- **摘要只随新对白更新**：模型返回当前说话者、指代和未完句；不确定就不填。
  新对白未给摘要时清掉旧摘要，避免沿用上一场景的人物关系；菜单不更新它。
- **稳定译名独立保存**：模型通过 `terms` 返回增量，例如 `Firebrand=火印;`，每项以分号结束。
  本地按原文合并（英文忽略大小写），不让模型自动改写已有译名；最多 32 项，每项原文/译名各 95 字节。
  过长或不完整条目会忽略，不会存半个词。译名不会因 3 分钟超时而消失，也不会被一次空响应抹掉。
- **隔离**：按 ROM 路径与目标语言分文件；多碟游戏优先用 m3u 路径。
  文件是 `.userdata/ai/ctx3-<哈希>.txt`，UTF-8 安全存储，临时文件写入成功后再原子替换。
  旧 `ctx-*.txt` / `ctx2-*.txt` 没有可信的整屏时间信息，不自动导入，原文件保留。
- **时钟异常**：记录来自未来或检测到时钟回拨时清掉短期内容并落盘，稳定译名保留。
- **手动清空**：`Options → AI Translate → 清空当前场景`，按 A 立即清掉对白和摘要，保留译名。
  读档、跳剧情或重开游戏后使用。若写入失败会提示，不假报清空成功。
- **开关**：`上下文`（`aiContext`）关闭时不注入也不更新记忆；重新开启后旧记录仍按原时间过期。

提示词把历史明确标记为参考数据：只翻译当前画面、不重复旧对白、不补写后文，冲突时当前原文优先。
时间只改变参考强度，不保证两张相近时间的截图一定属于同一场景。
所有记忆字段随同一次翻译请求返回，**不增加额外模型请求**。为控制响应开销，
历史输入上限为 4 KiB（含结束符），提示词要求摘要不超过 40 字、新增译名每屏最多 4 项；
本地仍可保存 6 屏，实际发送按预算选择。字节上限不等同于 token 上限，实际延迟仍取决于模型和网络。

### 提示词与排版（2026-09-30 改版二：0~1 坐标 + 整块给框 + 本地折行）

第一轮改的是「连贯性」（保留在下一节），第二轮改的是**坐标与排版的分工**：

1. **坐标只要 0~1 的小数**（`0.234` 这种），换算成内部 0~1000 由程序做。
   提示词里写清了定义（把绝对位置除以画面宽 / 高）、给了示例、给了反例
   （「不要写 0~1000 的整数、不要写百分数、不要写画面上的实际点数」），
   并要求它输出前自查一遍范围。**刻意不告诉它图片的像素尺寸** —— 说了它更容易按像素给值。
2. **一段话只给一项**。多行对话框 / 多行标题不再逐行拆条，而是给覆盖这几行的**整个矩形**、
   `zh` 给**完整的一整句**（不许自己换行）。原来那句「按中文语序分回各条」实测经常被它
   拆成几个各自成句的短句，读起来还是碎的。
3. **折行改在本地做**（`ai_fit_lines`）：按框宽逐字折、字号取「折完正好塞进框」的最大值、
   整块在框内竖直居中。中文断在字与字之间，西文靠空格断（不劈单词），
   并且**行首不许出现收尾标点**（`。，、！？；：）」』…` 这些会捎到上一行去）。
4. **擦除框会自己往外摸**（`ai_erase_grow`）：模型给的框常比原文小一圈（实测状态栏右边
   少 9%、对话框上边少 2%），只按框擦会在译文旁边留半截原文。现在擦之前逐档检查紧贴框外
   的一小条，只要那条里还有笔画就往外扩一档、笔画没了就停。判据要求那条里**同时**有底色
   和明显偏离底色的像素、且沿长轴交替出现 —— 整块异色背景或一条直线边界都不算，
   所以不会顺着画面里的色块边界一路糊出去。实测 5 个真实场景：需要时摸 3~8 档，
   不需要时一档都不摸；`aiDebug=1` 时日志里会写这次一共摸了几档。

**新的坑**：提示词 UTF-8 **2385 字节**，而 `ai_build_request` 里曾是 `char prompt[2048]`
—— 直接改会被**静默截断**。已把 `prompt` 加到 4096、`esc` 加到 8192（转义后约 2.4KB）。

### 提示词（2026-09-30 改版一：连贯优先，已被上一节取代）

**问题**：原提示词写着「同一个框里的多行文字分成多项」，模型就真的把一句被折成几行的话
逐行独立翻译 —— 每行各成一句、语序倒装、专有名词前后不一致（同一只怪在两处被译成两个
名字）。另外「译文尽量短」也在诱导它截断句子。

**当时的改法**（`ma_ai.c` 的 `AI_PROMPT_FMT`）：

1. `note` 挪到 `items` **前面**，并要求写「这是什么界面、整屏文字整体在说什么」——
   逼模型先把整屏读完再逐条出结果（`thinking` 是关的，这是最省 token 的"先思考"手段）。
2. 一句被折成几行的话**当成一个整体翻译**：先译成一句通顺的中文，再分回各条；
   **按中文自己的语序断行、不必和原文断行位置一致**。
3. 同一屏里的专有名词（人名/地名/怪物名/道具名/技能名）必须用同一种译法。
4. 明确「除已经是中文或纯数字以外一律要给译文」—— HP、STAGE 这类英文短标签也要译。
5. 「译文尽量短」改成「尽量不超出自己那一行，但别为了短而截断句子」。

改版二把第 2 条换成了「只给一项 + 本地折行」，第 1、3、4 条保留。

**旧版验收记录**（`bash tools/测试解析器.sh <响应.json>` 这套流程一直沿用）：
已用三种输入验证通过：note 前置的正常响应、**note 里含 `items` 字样与方括号的恶意构造**、

## 已知限制

0. **Overlay 保留原文**。粗描边能隔开译文周围的背景，但不会消除旁边的原文字。
1. **极窄标签会缩小字号**。当前按模型给出的可用区域排版，坐标偏小会限制阅读字号。
2. **坐标刻度仍是模型侧风险**。0~1 之后「按像素给值」基本没了，但 deepseek 这类模型
   的比例会随送图尺寸变；本地只在「明显不是 0~1 / 明显越界」时才换算，
   落在图内的像素值和 0~1 无法区分（见 `ai_boxes_normalize` 的注释）。真歪了就换百炼。
3. **模型给出的文字块相互重叠时，浮层也可能重叠**；仍需更准确的定位来彻底解决。
4. **极小像素字的 OCR 本身有歧义**。同一行模糊假名，deepseek 读成 `たびびとのうみ`、
   qwen 读成 `たてもの`/`たたかう`。译文跟着原文走，所以整句可能跑偏。
5. **依赖设备上的 curl**。NextUI 的 RetroAchievements 也是靠 `popen("curl ...")` 发 HTTPS 的，
   所以设备 rootfs 里应该有。代码里做了运行时探测 + wget 兜底 + 明确的错误提示，
   万一没有会直接告诉你。
6. **每次 0.9~8 秒**（看模型），交互是"暂停 → 翻译 → 看 → 恢复"，做不到实时。
7. **API key 明文存在 SD 卡**上。
8. **合并字体里有 14 个坏字**（康熙偏旁码位 U+2E85、U+2F07~U+2F11，FreeType 报
   `invalid outline`）。原版 M+ 和圆体捐赠字体里这些都是好的，是合并过程弄坏的。
   游戏文本基本不会用到这些码位，所以没修（改字体有把整份字库弄坏的风险）。
   扫描方法见 `~/Downloads/ai-translate-test/`；真机上遇到这类字形会跳过那一条，不会崩。
