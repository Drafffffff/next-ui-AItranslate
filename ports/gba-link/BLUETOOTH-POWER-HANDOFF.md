# Brick Mic 与蓝牙联机的开关交接

2026-10-08 用户报告：打开并退出掌机 Brick Mic 后，蓝牙联机提示蓝牙关闭。代码证据：Brick Mic launch.sh 若启动前蓝牙不在运行、系统开关也关闭，会在退出时调用 bt_init.sh stop；GBA helper 之前仅检查 Adapter1.Powered，服务或电源关闭就报错。此行为可能重现用户问题；本轮 SSH 暂时不可达，尚未观察到用户的现场服务状态。

修复放在 GBA 联机分支，不改变 Brick Mic、Mac 应用或其证书。用户选蓝牙创建/加入时，用 CFG_setBluetooth(true) 同步 NextUI 系统开关（该 API 自身落盘），随后由私有 helper 在后台准备无线电。UI 显示 Preparing Bluetooth，并可 B 取消。搜索、主机和客机共用相同准备步骤。

有适配器且已开机时不做电源/服务操作；适配器关闭时只调用正常 BlueZ Powered=true；只有适配器和 bluetoothd 都不存在时才调用已有系统初始化脚本 start。现有 daemon 正在恢复但适配器尚未出现时等待，绝不 restart/stop 已有服务。20 秒准备上限和私有控制 heartbeat 保留；取消不恢复关闭状态、不停止共享服务。系统原脚本首次初始化控制器包含现有 rfkill/hciattach 流程，仅在未发现适配器/daemon 的冷启动分支使用，未增加自定义 reset。

错误不会通过重启服务掩盖：总线、权限、脚本启动或开启电源失败返回明确准备失败。开启系统蓝牙是用户选择蓝牙联机的持续设置；即便随后取消搜索，也可在 NextUI 系统设置手动关闭。Wi-Fi/热点选择不修改该开关。

本地状态机验证覆盖：已开无需操作、适配器关闭只开机、服务关闭冷启动、已有 daemon 等待适配器、权限/启动/电源失败、取消时不重启服务。完整 Mac race/core 集成和 ARM 构建、包安装回滚需通过后才能部署。实际 Brick Mic 退出→联机、反向交接及取消体验由用户在掌机验收；不以离线状态机测试宣称实机交接已验证。
