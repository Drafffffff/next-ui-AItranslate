# 典型任务与修复示例

先 `read_game`；完整示例通过 `read_skill({module:"example/<id>"})` 加载，局部改动不需要读取整份模板。新建用 `write_game.lua` 完整代码，局部调整用同一工具的 `edits`；宿主合并后保存完整游戏。工具调用中的值来自当前项目与本次真实返回，不能复制示例身份、旧版本或假造成功结果。

## 1. 新建：小猫吃鱼，30 秒吃到 10 条就赢

调用 `read_game` 确认当前项目；使用猫 ID 1 和鱼 ID 3。实现方向键移动、HUD 计分/倒计时、取得目标后的重新生成、胜利与超时失败、O 重开。随机鱼在 HUD 下方，避开猫，并有有限尝试与回退。开始或重开不能继承上一轮目标和计时。

参考完整 `assets/examples/collect.lua` 的组织方式，根据用户要求调整。不要引入未要求的敌人或三条命。提交标题和具体摘要，例如“30 秒内吃到 10 条鱼获胜，方向键移动，O 重开；等待试玩确认难度”。写入成功 → 检查成功 → 发布成功后，才报告发布。

## 2. 修改：狗跑得慢一点，其他都不变

先读取实际源码，识别狗的移动速度和关卡增长；玩家速度、狗的数量、得分、生命、按键、鱼的生成和现有精灵保持原有行为。用 `write_game.edits` 精确修改有关代码；旧文本需要唯一，避免只用到处都出现的数字。省略 `sprite_overrides` 保留图像。

若原代码是 `dog.x=dog.x+dog.dx*dog_speed`，降低 `dog_speed`；不要把玩家 `speed` 一并降低，也不要直接用躲避示例覆盖原游戏。回复依据具体改动，例如“降低了狗的移动速度，其他规则和素材保持原样；按 START 试玩”。

若读到 `dog_speed=2`，可传 `{edits:[{oldText:"dog_speed=2",newText:"dog_speed=1.5"}],summary:"降低狗的移动速度"}`。若初始化与重开分别赋值，用一个调用的多个不重叠块一起修改，必要时带函数上下文；全部匹配同一旧源码。只换角色像素可只传素材覆盖；新增角色ID引用时一起传对应edits。

## 3. 修复：碰到两只狗，一下就掉光生命

局部修复思路：统一碰撞框，每次更新只允许一次扣血，并在后续更新逐帧减少无敌时间。

```lua
if invul>0 then invul=invul-1 end
local hurt=false
for i=#enemies,1,-1 do
 local e=enemies[i]
 if not hurt and invul==0 and overlap(player,e) then
  lives=lives-1
  invul=30
  hurt=true
  if lives<=0 then state="over" end
 end
end
```

`overlap`、`player`、`enemies` 和 `invul` 必须来自完整源码，重开时重置。不同游戏的无敌时长由实际机制决定，不能固定要求所有游戏都是 30 帧。

## 4. 网格：蛇换方向太快，或者吃不到食物

增长型蛇/网格用占用表查询格ID，绘制地板后遍历实体；不要每个可见格都扫描完整蛇身。食物在事件发生时枚举空格，满盘明确结束。

按键每帧采集，移动只在网格节拍执行；一拍只接受一次方向转弯，拒绝直接反向。采样和移动不能都挤到节拍帧，否则短按会丢失。蛇身与食物都用格坐标，绘制时才乘格子大小。

食物生成先枚举空格，再选一个；填满棋盘时胜利，避免无限随机。没吃食物时，碰撞检测允许进入本拍会移走的尾格；吃食物时尾巴不会移走，要检查完整蛇身。参考完整 `assets/examples/snake.lua`，不要用矩形像素运动修改已有网格逻辑。

## 5. 平台：按住 O 会连跳，落地抖动或穿墙

上升沿避免把长按与 `btnp` 的重复触发当成每次新跳跃：

```lua
local o=btn(4)
local jump=o and not old_o
old_o=o
if jump and grounded then vy=-3.5 end
```

水平、垂直分别移动和解决碰撞。下降碰到平台后把角色底部对齐平台顶部、`vy=0`、`grounded=true`；撞到天花板时修正角色顶部且不能标记落地。先处理角色大小和平台位置，再检查目标/危险。参考完整 `assets/examples/platform.lua`；片段不是完整的平台游戏。

## 6. 自定义：把角色换成蓝色机器人

先 `read_game` 看现有自定义 ID；复用已有角色 ID，或选一个空闲 ID。以下只展示 `write_game.sprite_overrides` 中的一条 8×8 图像：

```json
{"id":32,"pixels":["00cccc00","0cccccc0","0c0cc0c0","0cccccc0","00cccc00","0cccccc0","0c0cc0c0","0c0000c0"]}
```

完整源码用 `spr(32,player.x,player.y)` 绘制；如果 ID 32 已被另一对象使用，选其他可用 ID，不能覆盖它。图片行是颜色索引，不是 RGB、十进制列表或 Unicode 方块。要清空某个自定义图像时显式写 8 行 `00000000`；传空覆盖数组只表示保留。

## 7. 工具失败、只想讨论、需求暂不支持

- `write_game` 返回像素格式错误：修正为 8 行×8 个 hex 字符，重新提交有关edits/覆盖；整批失败时草稿没有部分改变，成功后重新检查。匹配失败或重复时重新读取当前源码，扩大oldText上下文。不能在失败后继续发布。
- `check_game` 报错：按真实错误修复，重新写入、重新检查，再发布；不能把检查与发布合成同一批调用去猜检查成功。
- 只成功写草稿、发布失败：说“草稿已保存，发布未完成”，保留当前已发布版本；不假造一个新版本号。保存/网络持续失败时停止，不反复消耗工具轮次。
- 用户问“你觉得还能怎么改”：先讨论选项，不擅自写入。普通对话不会产生新的游戏版本。
- 用户要求加入或修改音乐：按 `music` 模块 读取现有音符与声部，提交结构化覆盖并连接场景/事件，保留其他资源。
- 用户要求重启后记住最高分：当前没有永久存档工具；可提出本次运行内最高分，但不能把它说成已完成原需求。
- 用户说“刚才取消了，接着改”：重新 `read_game`，基于实际草稿继续，确认哪些改变已写入而哪些未发布。

## 8. 定点数：长时间运行以后分数突然变负

16.16 数值不是无限整数。不要用一直增长的总帧数、`score*100000` 或系统毫秒时间。把计数拆成短周期与有界累计，例如：

```lua
tick=tick+1
if tick>=30 then
 tick=0
 seconds=min(30000,seconds+1)
 score=min(30000,score+1)
end
```

在生命周期初始化中建立这些变量。倒计时达到零后转结束状态，不继续递减。参数选取服务于用户玩法，不要求所有游戏的分数上限都相同。

## 9. 修改前的影响范围与修改后的源码复查

把本次需求定位到具体状态和变量：例如“敌人慢一点”影响敌人位移及随关卡变化的系数，“多一条命”影响初始化、HUD和失败条件，“换角色”影响精灵、帧表和可见大小。读取调用这些变量的位置，避免只改初始值却被重开或每帧赋值覆盖。保留当前项目身份、按键、关卡、素材和无关规则；完整示例只帮助理解算法。

以源码确认：初始化后能进游戏；操作能影响目标对象；目标和失败条件确实可达；结算只触发一次；结束后规则停止；重开重新建立本轮状态。修复后还要检查原有路径：增加无敌帧不能让角色永久无敌，修正胜利判断不能让空关卡立即获胜，改速度不能令跳跃不可达。以上是阅读代码的依据，不称为已试玩。

## 10. 子弹、敌人和关卡数量

- 从每个实体的碰撞、移动和绘制函数反查它们读取的字段，再核对全部创建、重生和重开路径。例如 `over(...,foe.x+2,foe.y+2,4,4)` 要求敌人出生时就有数值 `x/y`；`foe={x=106,vx=.7}` 语法合法，但运行到碰撞便会因缺少 `y` 报错。应按场景布局在实体初始化处补坐标，不能用 `foe.y or 0` 掩盖错误并把敌人移到屏幕顶端。可用 terminal 对确定的初始化数据和纯规则写断言；它不会运行 PICO-8 图形 API，也不证明已试玩。
- 子弹、粒子、敌人分别设数量上限和离屏/过期清理。新对象满额时延后生成或丢弃；每帧的随机尝试数有上限，不能为了生成一个目标循环到成功。
- 逆序遍历删除对象，防止跳过后继对象。一发消耗型子弹首次击中后就退出目标循环，避免命中所有重叠敌人；同一枚奖励只计分一次。
- 高速小对象容易越过碰撞框。先判断每帧位移是否大于障碍厚度，必要时采用有限分步移动或线段碰撞。分步数有限，不能依赖无限细分。
- 难度增长使用有界速度、生成间隔下限与对象上限；“更难”优先调整一两个有关参数，不同时改变输入、碰撞框、生命和计分。
- 增加地图时检查起终点连通、角色占格、门/钥匙状态、推箱子不可逆角落、平台跳跃的水平距离和高度。现有工具不能证明随机地图一定可解；小规模关卡优先用明确的布局和有限规则。

## 11. 长按、暂停和重开边沿

在状态分支之前采集本帧按键，并更新 `old_o/old_x` 等边沿状态。只在游玩分支里更新旧状态，会把结束页面上一直按住的键误判成一次新按下。重开函数不要把仍按住的键记录清零，导致下一帧重复重开；它只重置本轮游戏状态。

如果用户要求游戏内暂停，使用未占用的 O/X 及明确提示。暂停期间停止规则与计时；恢复时保留位置、关卡和生命。宿主 START 是试玩入口，游戏代码不要假设能收到它或调用工坊操作。画面恢复 `camera/clip/pal/palt` 后再画 HUD，避免上一场景的变换影响菜单和下一轮。


## 保留生命后的待发球/复位

丢掉一条命后的待发球是游玩子状态，不一定返回标题。列出每个状态×按键的实际动作：待发球时O必须能调用launch，O长按不能再次发球；不能只在title/over分支处理它。复位清理球速、遗留碰撞与能力时序，保留剩余生命；归零进入失败，终局才停止动作。检查失去第一条命后的完整路径，首局能启动不证明恢复可玩。
