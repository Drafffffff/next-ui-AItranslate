# 平台动作：让跳跃可控

依据：Celeste Classic 的 `player.update`、`move_x/move_y`，To A Starling 的 `p_update`。版本和位置见 `references/library-cases.json`；下述是工坊实现方法，不是可直接提交的原作代码。

## 先确定运动和输入的契约

方向键移动，O跳跃，X用于用户指定的冲刺/交互。集中保存跑速、加速度、减速、重力、跳跃初速度、最大下落速度、跳跃缓冲和离地容错。具体数值由关卡尺度决定。

Celeste 原版30 Hz有4帧跳跃缓冲、6帧离地容错；To A Starling 的60 Hz窗口为10帧。这是不同作品的选择，不是通用常数。工坊可从约100–170ms的短窗口起步，根据试玩调整。

每次 `_update` 的职责：

1. 在所有状态分支前采集按键，建立按下/松开边沿。按下O设置缓冲倒计时；长按不能反复刷新。暂停/结束也更新旧键状态。
2. 用上一次碰撞得到的 grounded 建立离地容错，离地后倒计时。若缓冲有效且 grounded/容错有效，消费这次请求，设置起跳速度，并清空缓冲和容错，禁止同一次请求二次跳跃。
3. 地面与空中分别靠近目标水平速度；无输入时减速。持续按住只移动，松开跳跃时可截断仍向上的速度，形成短跳/长跳。若使用顶点附近较小重力，不能令角色悬空不落。
4. 累积小数位移，分轴做有限像素步进或可靠扫描碰撞。下降撞地修正脚底并清零vy，向上撞顶清零vy但不标记着地；水平碰撞不清掉垂直运动。
5. 本帧落地后若还有有效缓冲，可消费一次落地跳跃；不要让步骤2和步骤5同时执行同一请求。最后处理危险、终点和视觉反馈。

小数位移的意图：`remainder += velocity`，提取带符号的整数步数并从 remainder 扣除，移动相同步数；不要每帧 `flr(vx)` 让慢速移动丢失或负向偏快。从1到abs(steps)循环，不能从0多走一步。碰撞后清掉该轴速度和余量。最高速度必须小于所采用有限步进预算可覆盖的位移；不要截断步数却继续扣掉整段余量。

## 关卡必须配合物理

先用参数推导可达跳高/距离，再摆平台和终点。试验区含：平地、一个矮台阶、一个接近最大可达间隙、窄通道、一个可绕过的危险。初次挑战留余量，不把理论极限当作必过路线。角色视觉可为8×8，碰撞框可略小但保持稳定、明确；冲刺拖尾和头发不是碰撞体。

冲刺要有次数、方向和恢复规则；斜向归一化，避免更快。只有允许的恢复事件补次数，进入房间/死亡时明确重置。Celeste 的头发颜色显示冲刺可用性，可借鉴“能力状态通过角色可见变化表达”，不照搬原图。

## 针对性源码推演

| 情况 | 应看到的逻辑结果 |
| --- | --- |
| 在落地前短按O、随后松开 | 有效窗口内落地消费一次请求；太早按则自然过期 |
| 刚走离平台短按O | 容错窗口内起跳，窗口外拒绝；落地后才能再获得 |
| 一直按O直到落地/死亡重开 | 不自动连跳，不重复重开 |
| 向天花板跳、斜向撞墙角 | 不悬在顶上、不误恢复跳跃次数、不穿墙 |
| 暂停/换房/检查点复活 | 计时、余量、速度和镜头按设计保留或重置，不继承旧碰撞 |
| 调跑速/重力后 | 终点仍可达；改变的不仅是一个看起来相近的数值表达式 |

静态推演只能发现逻辑矛盾，缓冲是否舒适、跳跃弧线是否好玩仍需SR试玩。小改动保留已有技能和布局，不用平台模板覆盖当前项目。
