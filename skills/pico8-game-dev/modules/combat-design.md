# 战斗：预判、命中与恢复

依据：Just One Boss 的动作序列、laser_attack与phase_change，Buns: Bunny Survivor的damage_player、wave_update/spawn_wave。详见研究清单；不是要求所有游戏加入Boss和群敌。

## Boss或敌人的状态机

优先 `ready → telegraph → active → recovery`。每段有有界倒计时；进入状态设置一次动作参数，更新时推进，结束再转换。Just One Boss的激光会先站位/摆姿态、等待，再发声与生成危险光束，持续后恢复；不是每帧随机选择攻击或在玩家脚下瞬间生效。

用约0.4–0.8秒预告作为首版可调起点，不是通用难度标准；按30 Hz转换帧数。危险区、朝向或锁定点在预告时可看见；攻击开始后是否仍追踪由机制决定。玩家从可移动范围应有逃生路径。恢复窗口给玩家反击/取目标的机会。

阶段变化由生命或目标事件触发一次，清旧弹幕/动作队列和旧计时器；死亡/胜利优先于新攻击生成。不移植原作的异步Promise/协程调度器，少量显式状态已足够。加入第二招前先让第一招的预告、伤害和恢复闭合。

## 敌人职责产生不同应对

例如追击者迫使移动、固定炮台迫使找掩体、冲锋者锁定后直线冲刺。先做1–2种有明显区别的行为；仅颜色/血量不同不是新的战斗选择。新增能力要接到玩家决策，例如攻击期间减速、击败特定敌人恢复有限技能。保留用户原有玩法，不把一切都改成自动射击。

实时攻击使用明确朝向/瞄准向量，P8 `atan2(dx,dy)` 与 `cos/sin` 约定先看 `api`，用上/下/左/右四个向量核对。对屏幕坐标向下为正的体系，不把数学库的常规sin符号直接搬入。

## 一次受击对应一次反馈

Buns以无敌计时防止同帧或紧邻帧扣空生命，并连接声音和震动。工坊统一damage入口：检查生命状态和invul，成功后扣血、设置无敌、触发视觉/声音；在结束状态或invul>0时拒绝。玩家闪烁/描边表达保护，短暂停顿/轻抖表达重击，不让普通连发每次都停游戏。

敌人受伤、死亡、奖励分别单次结算；消耗型弹丸第一次有效命中后失效退出。boss.hp<=0先转结束状态，不能先生成下一招再结算。奖励实体有collected/dead标记，同帧多个拾取路径不重复得分。

## 波次与帧预算

Buns的波次有start_time、interval和剩余count，并在完成后移除；可借鉴有限时间表。原作大规模分桶不等于本机任何数量都流畅。

初版可从敌人12、子弹24、粒子24的上限起步，再按实际复杂度/试玩调整；这不是已测性能。生成在离玩家足够远的区域，随机尝试有限，找不到位置则延后，不在玩家身上生成立即伤害。增加难度一次调整一种行为或间隔，并保留数量上限、间隔下限和休息窗口。

每帧清理过期/离场对象。少量敌人用直接遍历；数量扩大时统一分桶复用表，避免每个敌人每帧重新建立整份列表。粒子由有意义的事件产生，满额可丢弃表现对象，不能丢掉规则状态。

## 源码推演

首帧不直接受伤；同帧碰到两个敌人最多一次扣血；无敌结束后能再次受伤；预告位置与真正危险区一致；攻击结束清危险实体；阶段转换不残留旧招；最后一击不再生成攻击；暂停停止波次时间；重开恢复敌人、玩家和计时；长时间运行数量/倍率有界。实际手感、可读性和难度需要用户试玩，不能把此推演说成已自动测试游戏。


## P8方向：画面、预告与实际命中共用依据

屏幕向下dy>0；P8的sin(.25)=-1、sin(.75)=1。向上/向下动作的角度分别为.25/.75，右/左为0/.5。不能拿普通sin正弦方向推P8角度。斩击图像和碰撞区域用同一朝向；扫射从上方Boss朝场地内下方发射，应使用sin为正的角度区间，预告也对应实际射线。列出每个朝向的向量，逐项核对绘图和规则，而不是两份相反的手写表。
