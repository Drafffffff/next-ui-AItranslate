# 音乐与音效：创作、状态与资源

本模块仅在新增或修改声音时加载。根据玩法安排轻量循环BGM与必要的交互音效，尊重用户要求的安静模式。修改已有游戏时保留现有音乐及资源，不因无关改动突然添加或替换曲目。

## 可直接使用的声音

内置音效：0 收集，1 跳跃，2 受伤，3 胜利，4 失败，5 推动/步进。6/7 未提供，不可假设有声音。BGM 从 music pattern 0 或 6 开始：

- `music(0,200,7)`：MIT 社区 M2tias raycaster 的 Kajam 主题，SFX 4..9 已重映射为 8..13，音量限制到 3；pattern 0..5 循环，声道 0..2，声道 3 给交互音效。原卡带与许可随 Skill 保存。
- `music(6,200,3)`：工坊原创轻快双声部循环，SFX 14/15，声道 0/1，声道 2/3 留给音效。
- `sfx(0,3)` 等显式在声道 3 播放交互声；`music(-1,200)` 停止并淡出 BGM。无需导入 WAV/MP3，也不能把音频文件当 tracker 数据。

新一轮开始或场景改变时调用一次 `music`，不要在 `_update` 每帧或 `_draw` 里反复调用。结束时先停止 BGM，再播放结尾音效；重开停止遗留交互音 `sfx(-1,3)` 并重新开始 BGM。碰撞无敌帧同时限制受伤音触发。循环只由 pattern 标记控制，不靠逐帧重启。

```lua
function reset_round()
 -- establish all round state here
 sfx(-1,3)
 music(6,200,3)
end
function finish_round(won)
 state=won and "win" or "over"
 music(-1,200)
 if won then sfx(3,3) else sfx(4,3) end
end
```

这是局部片段。完整游戏仍须定义初始化、状态、输入和绘制，不能只提交声音播放器代替玩法。给已有游戏加音乐时，改动重置/状态转换与交互事件，保留其难度、地图、生命与计分。

## 编写自定义曲目

本次 `read_skill({module:"music"})` 的 `project_assets.audio` 返回当前项目全部SFX和pattern，`project_assets.catalog` 是可用内置资源。它们是宿主读取的实时草稿数据，与教学正文分开；编辑之前结合 `read_game` 的当前源码。通过 `write_game.sfx_overrides` 与 `music_overrides` 合并局部覆盖，省略或空数组保留全部已有声音。自定义 SFX 用 16..63；自定义 music pattern 用 8..63。内置槽位保留，想改变内置曲风就新建自定义并改源码引用。

一条 SFX：`{id:16,speed:16,loop_start:0,loop_end:0,notes:[...]}`；`notes` 必须恰好 32 个 `[pitch,waveform,volume,effect]` 整数数组。音高0..63、波形0..7、音量0..7、效果0..7。不足32个音符的剩余行用 `[0,0,0,0]` 补齐；休止由 volume=0 表达，pitch=0 是 C0，不是休止。

音高每12个值一八度，C2=24、D2=26、E2=28、G2=31、C3=36。默认波形0三角、1倾斜锯齿、2锯齿、3方波、4脉冲、5管风琴、6噪声、7相位器；不使用8..15自定义乐器依赖。效果0无、1滑音、2颤音、3降音、4淡入、5淡出、6快速琶音、7慢速琶音。

speed 是每行持续的tick数，不是BPM。本工坊锁定fake-08用每speed单位183个22,050Hz样本：一行秒数约为 `speed*183/22050`；speed16一行约132.8ms、32行约4.249秒。若每拍4行，BPM约为 `60*22050/(183*speed*4)`，speed16约113 BPM；这是该实现的时值，不要写成精确1/128秒或120 BPM。不要把speed当BPM，整数更大是更慢。推荐先8..24并使用音量2..4，给高频方波、噪声和多声部留出余量。

通常让单条 SFX 自身不循环，`loop_start=0,loop_end=0`。loop_end=0而loop_start>0表示有效长度（1..32行）；真正SFX循环必须满足0<=loop_start<loop_end<=32。背景乐由music pattern循环，更容易控制停止和换场景。

一条 pattern：`{id:8,channels:[16,17,-1,-1],loop_start:true,loop_end:true,stop:false}`，四项对应声道0..3，-1为静音，其余必须引用本次合并后确实存在的SFX。这一条会循环自己。多段曲目使用连续pattern ID，首段loop_start:true，尾段loop_end:true；普通中间段下一ID必须存在。短结尾用stop:true，不能同时loop_end:true。loop_end必须有不大于自己的loop_start；全静音pattern只能设stop:true。

最小作曲例：旋律 SFX16 的每4行起点依次用36/40/43/40/38/41/45/43，波形0、音量3、效果5，其余行休止；SFX17用24/29/28/31低音，每8行换音、每4行触发一次，音量2。两者speed16；pattern8如上，调用 `music(8,200,3)`，音效仍在声道3。提交前实际展开32行数组，不写省略号、占位符或伪随机音符。

## 社区曲目与音乐体验

随包提供的 Kajam 曲目来自 `M2tias/pico8-raycaster` 的 `carts/raycastkajam.p8`，固定提交与 MIT 许可见 `assets/community/sources.json`。`assets/audio.json` 标明原SFX编号、槽位重映射和降音量；保留原卡带与作者许可。Snak 原作也可学习音乐状态连接，但不会把其 GPL 素材假设成无条件自由素材。

创作先定氛围、节拍、调性，再写短动机；旋律、低音和节奏互相留空间。安静解谜优先低音量双声部，生存/迷宫可用社区三声部循环；不要所有游戏都强制同一曲目。循环衔接避免突然的音区跳变；跳跃/命中是短反馈，不能每帧重复。用户要求调慢音乐时主要调整相关SFX的speed；不改变角色速度。用户要求换旋律时保留其他曲目与音效槽位。

格式检查验证数据范围、引用及章节编码；不代表旋律好听、无爆音或 Brick 外放已听验。说明使用的曲目和待听点，依据实际用户试听调整。工坊 SR（物理Start）启动游戏，由 P8 运行器合成音乐；应用对话页不连续播放游戏 BGM。

## 从真实游戏提炼声音连接

掌机库研究定位见 `references/library-cases.json`。Combo Pool的`docoll`把合成等级、连击/得分和不同声音接在同一次结算里；Just One Boss的`shoot_laser`在危险光束生成前安排声音与等待；Buns的`damage_player`用无敌状态限制受伤声重复。借鉴事件和时序，不复制原曲。

为当前玩法建立小型事件表：动作请求成功→短操作声；危险将开始→能辨识的预警；实际命中/受伤→单次反馈；目标完成→结果声并换/停BGM。拒绝动作与成功动作可以有区别，不是任意按键都播放同一声音。BGM表现氛围，关键预警在视觉上也成立，不要求玩家必须开声音才能过关。只用实际存在的音频槽位，保持声道分工和对象/事件去重。


## 听起来卡：先核对数据，再改一项

音乐呼吸、音频欠载和反复重播是不同原因。用户已说明移动流畅、只有音尾被切掉时，先检查当前发布曲目；源码/音符数据只能证明编排，不能证明扬声器输出没有欠载。记录本轮改动及一个待试听点，不能凭换波形或减少声部声称性能问题已解决。

- pattern6是短音轻循环：SFX14音量交替3/0，SFX15每4行响一次，具有刻意休止。不能把它当作持续连奏，或声称它适合修复所有断音。保留社区Kajam为有来源的听感参考，不因用户要求连续就抹掉所有休止。
- 连贯、断奏、短音反馈分别设计。先标清主旋律每个音持续几行、休止多少行、结尾是否淡出；`[3,0]` 是响一行后静音，不是两行延音。同音持续可保持pitch/waveform和非零音量，仅在需要的末行使用轻微收尾；是否自然以试听为准，不能仅凭填满32行保证连奏。
- 持续音示意：同一pitch的4行音量3/3/3/2，前三行effect0，最后一行可试effect5。断奏示意：音量3/0并保留明确的节拍。它们是编排片段，完整32行及适合该乐句的speed仍需展开提交。社区原作数据不要标成这些原创示意的来源。
- 操作音效用独立自定义槽16..63，例如speed4、loop_start2/loop_end0表示2行有效长度（约66ms），其余行补静音。成功动作才触发一次；连续移动按动作节拍触发，不每个画面帧重播。不要拿BGM的完整32行低音SFX当步进声。高频连续反馈可独立设置短冷却，不改变移动节奏。
- 改曲目后核对实际提交的speed、32行pitch/volume/effect、有效长度、循环边界、声道与源码调用；核对文字摘要是否真的对应音符。一次只改主要因素，保留旧曲便于对照。保留BGM的声道也会被显式`sfx(id,channel)`抢占，mask不会阻止显式覆盖。
- 开发环境可统计核心PCM中的休止时长、峰值、事件次数和循环切换；这些是诊断信息，休止不自动判失败。Agent没有声音观察/自动试玩能力；不得声称已测缓冲、已听验、无爆音或实际帧率达标。
