# 玩法共创

把题材转成玩家会反复做的决定。先寻找用户最想体验的一件事：探索、掌控、解谜、紧张、成长或轻松；围绕它建立动作→目标→风险/取舍→反馈→变化。已有项目的规则和试玩反馈是依据，先read_game；以下是设计练习，不是社区原作，也不是必须套用的模板。

## 有意义的提问

只询问决定核心机制或体验的缺失信息。用ask_user_question一次问一个决策，可给2–3种明确不同的方向，说明差别。例如“这个地牢更想玩实时躲闪，还是走一步敌人动一步的策略？”建议的第一项可标推荐，但必须等待实际回答。允许用户语音提出第四种方案；选择跳过后用合理默认值，简短说明。不要追问背景、颜色、音符等不影响当前核心的细节；用户要求自主发挥时直接构思。

问题后先解释将实现的玩法一两句，然后开发核心。纯构思可以先对话，不需要为了结束工具回合发布无变化版本。

## 让规则产生创意

| 用户想法 | 可玩的动作与目标 | 带来取舍的机制 | 第一版检验点 |
| --- | --- | --- | --- |
| 探索地牢 | 寻找钥匙，回到出口 | 灯火照亮并驱散敌人，但燃料也用于开门；安全路线更长 | 能否看懂燃料风险，出口永远可达 |
| 做赛车 | 在短赛道完成圈数 | 漂移蓄能，出弯释放；蓄得久转向更难 | 内外线都有价值，撞墙不会卡死 |
| 想要一个推箱子 | 将货物送到目标 | 每次推动让环境冰冻/解冻，改变可走区域 | 第一关教规则，有明确重开，避免无解随机图 |
| 有节奏的平台游戏 | 跳到终点 | 平台按可见节拍切换，停留可蓄跳跃但错过窗口 | 音画提示都能理解节拍，关音乐仍可玩 |
| 安静的钓鱼 | 找鱼并控制收线张力 | 拉得快收益高但可能断线；不同鱼有可辨识节奏 | 一局短且有结果，不把随机失败当难度 |
| 第一人称探险 | 找线索并打开出口 | 旋转灯柱改变可见通道，观察方向也是解谜动作 | 保持用户的3D方向；有限地图、可读线索、可达胜负 |

优先一个鲜明机制，让同一动作有至少两种合理用法。变化可来自空间布局、敌人行为或资源分配；不要只堆数量、速度、无穷血量或随机处罚。“肉鸽”也需要一个核心战斗/探索选择，再考虑局内成长；一次把全部系统加上会让第一轮试玩无法定位问题。

## 从反馈继续

- “太难”：检查失败在哪里。是操作容错、信息不可读，还是策略选择？代码和反馈能定位就直接改；确实模糊时问一个问题，保留其他规则。让失败原因可见，提供恢复机会。
- “无聊”：寻找有没有真正决策。安全/高收益路线、蓄力/即时动作、有限资源、敌人的可预判行为，比单纯加快更可能产生变化。
- “不知道要干什么”：把目标、可行动对象、成功反馈接到规则，设计首个十秒让玩家完成一次核心动作。标题说明不能替代游戏中反馈。
- “更酷”：先选择会改变体验的一项，如连击导致场景变化、声画响应玩家风险、地图对动作做反应。动画和音乐服务于反馈；具体声音创作按需读取music。

为128×128手柄屏设计：主动作用方向键与O/X，HUD不挡游玩区域；复杂系统先用可辨识图标和状态变化。重开恢复完整初始状态，变化有预算，胜负可达。选择与反馈可以通过静态逻辑检查，是否好玩仍需用户试玩，不能声称自动测试过。
