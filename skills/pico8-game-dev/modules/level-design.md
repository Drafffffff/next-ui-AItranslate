# 探索与关卡：空间、依赖和恢复

依据：Dusk Child `moveplayer/checkpointnow/dienow/respawnnow`，Into Ruins `genmap/postproc`。研究清单定位的是实际源码；学习房间状态和连接流程，不复制整个地图或素材。

## 小关卡先安排一次有意义的体验

首个区域安全展示一个动作；第二处让这个动作解决明确障碍；第三处组合已学规则并到达结果。用路口、位置、门、危险和资源产生选择，不用更长走廊填内容。初版可以只有一个精心安排的房间；不强制全部游戏做三关。

目标在玩法中可定位：远处出口、可辨识钥匙、变化的门、可见任务进度。首次成功后及时反馈。离开房间或失败恢复尽量短，让玩家不必重新读长说明或重走无意义路段。

## 统一世界与场景状态

每个scene存自己的布局/碰撞、实体、出生点、出口和一次性事件。玩家和实体保存在世界坐标，渲染用 `camera(cx,cy)`；HUD前调用 `camera()`，不能在地图绘制之前就恢复镜头。输入、碰撞、门和触发都用同一世界坐标单位，绝不用被镜头减过的屏幕坐标做地图碰撞。

进入新场景时切换地图和实体列表、设置合法出生点、重置速度/碰撞余量/镜头过渡。不要让地下室继续用地表地图；不要靠清空enemies后忘记填新敌人。场景的数据初始化要在更新前完成。

同一钥匙/碎片/宝箱在场景状态里记录已领取；只移除本帧显示对象不足以防止重新进入时无限领取。门的打开状态也属于逻辑数据，绘图不是唯一依据。

## 检查点恢复完整状态

Dusk Child同时保存出生位置、物品和门/灯等环境状态。工坊检查点是当前运行内快照，不是永久存档工具。按玩法决定恢复时保留哪些进度，将这些字段集中在同一个checkpoint结构；死亡入口停止规则，复活重置角色速度、受击/动画、镜头和必要实体，恢复环境快照。

不要只把x/y移回起点，却保留已消耗钥匙和重新锁上的门；不要把浅拷贝当快照导致之后的地图修改污染检查点。已经规定死亡保留进度的游戏按原规则做，不盲目复制Dusk Child。

## 生成地图先保证约束

Into Ruins有区域检测与连接处理，生成并非只撒随机墙。工坊没有任意地图导入，使用Lua数组。小首版优先手工布局，随后再引入有限模板/随机连接。

需要随机探索图时：

1. 建立封闭边界和合法起点。随机雕刻不触碰外围墙，地图外按实墙处理；格可走还需考虑角色实际半径。
2. 从起点做有界队列BFS/洪泛，记录reachable；每个格只访问一次，节点上限=地图格数，不能递归到无限深。
3. 在reachable内选出口/道具，起点距离应服务于玩法；出口不能与起点重叠。门钥匙按顺序验证：不开门时钥匙可达，取钥匙后能开门，再验证出口。普通连通不证明带钥匙依赖可解。
4. 若候选不满足，有限次重新布局/连接，最后回退到已知合法的小布局；无界repeat-until不是保障。
5. 针对平台、推箱子、迷宫分别检查跳跃能力、推箱死角或射线外围。一个BFS不能同时证明所有类型可玩。

探索不必清遍所有角落才有价值，支路应带来资源、线索、捷径或风险。危险/敌人位置给玩家应对空间；传送出口不紧邻立即伤害。

## 关卡与恢复的源码推演

起点落在可站立区域；至少一条符合实际行动能力的成功路径；需要的钥匙不锁在自己的门后；滚屏后拾取/战斗碰撞仍对应画面；切地下室用地下室数据；回到旧房间不重复领碎片；连续死亡/重开不留下旧镜头或空关卡；随机连接不打开外围墙；无合适候选走有限回退。以上是源码和布局依据，不能声称已遍历证明随机图永远可解或已试玩完成。
